thoraxe.bulk_ensembl.biomart module

biomart: download one exon table per species from the BioMart of a release.

transcript_query asks BioMart for the exon table of each gene. Here the same query (same 14 attributes, same dataset) is sent once per species without the gene filter, to the BioMart of the requested release:

  • the archive site of the release (ARCHIVE_HOSTS) or --biomart-host;

  • a host is used only if its mart registry advertises “Ensembl Genes <R>”, so that a dump never silently comes from another release;

  • the answer must end with BioMart’s completion stamp [success], so that a truncated answer is never stored.

thoraxe.bulk_ensembl.biomart.ARCHIVE_HOSTS = {112: 'https://may2024.archive.ensembl.org', 113: 'https://oct2024.archive.ensembl.org', 114: 'https://may2025.archive.ensembl.org', 115: 'https://sep2025.archive.ensembl.org', 116: 'https://jun2026.archive.ensembl.org'}

Archive site of each Ensembl release (https only).

thoraxe.bulk_ensembl.compara module

compara: gene trees and orthologs from the Ensembl Compara bulk files.

transcript_query asks, per gene,

  • tree.nh: REST /genetree/member/id/<species>/<gene>?nh_format=full;

  • the orthologs: REST /homology/id/<species>/<gene>.

Here both come from the protein_default collection of Compara:

  • Compara.<R>.protein_default.nh.emf.gz: every gene tree (Newick) and its members, indexed in trees.sqlite;

  • Compara.<R>.protein_default.homologies.tsv.gz: the homology pairs of one species, indexed in homologies.sqlite for the query species.

The homology file of a species does not hold all of its pairs: in release 115, the human file lacks every pair whose other gene belongs to cricetulus_griseus_picr, equus_caballus, mus_musculus, ovis_aries or sus_scrofa. Those pairs are only in the files of these species, with the human gene as homology partner. The index therefore reads the query species file and, in reverse, the files of the other downloaded species. missing_homology_species finds the species whose file is needed for a complete index.

A tree from the EMF dump has the same leaves, labels and branch lengths as the REST tree; the order of sibling subtrees can differ, as it does between two REST calls.

thoraxe.bulk_ensembl.compara.DEFAULT_HOMOLOGY_SPECIES = {'homo_sapiens': ['cricetulus_griseus_picr', 'equus_caballus', 'mus_musculus', 'ovis_aries', 'sus_scrofa']}

Species whose homology file carries human pairs absent from the human file (Ensembl release 115, see the module documentation).

thoraxe.bulk_ensembl.download module

download: fetch the bulk files of one Ensembl release.

From the FTP site (https://ftp.ensembl.org/pub/release-<R>/), each file is checked against the CHECKSUMS file of its directory (BSD sum, as Ensembl publishes it):

  • Compara: the protein_default gene trees (EMF) and the homology TSV of the query species and of the --homology-species;

  • for each species: the complete GTF, the unmasked toplevel genome and the core database tables that tsl.csv needs. By default, the species are the query species and every species with an ortholog of it in the Compara homology files (199 species for homo_sapiens in Ensembl 115, about 120 GB).

From BioMart: one exon table per species (see biomart).

Existing files that match their checksum are kept, so an interrupted download can be resumed by running the same command again.

thoraxe.bulk_ensembl.sequences module

sequences: sequences.fasta from the genome FASTA and the GTF of each species.

transcript_query writes one record per exon returned by REST /overlap/id/<gene>?feature=exon (every exon, of any gene and biotype, that overlaps the gene), with the sequence from REST /sequence/id and the description <coord_system>:<assembly>:<seq_region>:<start>:<end>:<strand>.

Here the exons and the gene spans come from the GTF (indexed in SQLite) and the sequences from the unmasked toplevel genome, decompressed once and indexed with a samtools-compatible .fai file. The sequence of an exon is the genomic slice of its span, reverse complemented on the minus strand (whole exon, UTRs included). The coordinate system and assembly of each sequence region come from the genome FASTA headers.

Bulk files hold every exon, whereas REST /sequence/id silently skips some exon ids (e.g. of some lncRNA genes overlapping the queried gene). The extra records do not change thoraxe’s results: thoraxe only reads the exons listed in exonstable.tsv.

thoraxe.bulk_ensembl.tsl module

tsl: the rows of tsl.csv from the core database dump.

transcript_query writes, for every queried gene, one tsl.csv row per transcript returned by REST /overlap/id/<gene>?feature=transcript: every current transcript of any gene (any biotype) that overlaps the gene on the same sequence region. The eight columns come from these REST fields:

Module contents

bulk_ensembl: build transcript_query’s input folders from Ensembl bulk files.

transcript_query asks the Ensembl REST API and BioMart, gene by gene, for the files that thoraxe reads from <gene>/Ensembl/. This subpackage builds the same files from the release-wide files that Ensembl publishes on its FTP site and from one BioMart dump per species, downloaded once:

file

online source (transcript_query)

bulk source

tree.nh

REST /genetree/member/id

Compara EMF dump

orthologs

REST /homology/id

Compara homology TSV

tsl.csv

REST /overlap/id?feature=transcript

core MySQL dump

exonstable.tsv

BioMart, one query per gene

BioMart, one query per species

sequences.fasta

REST /overlap/id?feature=exon and /sequence/id

genome FASTA + GTF

ensembl_version.csv

REST /info/eg_version

release number

The bulk folder is prepared once with ensembl_bulk download and ensembl_bulk index, then transcript_query --bulk-dir <folder> reads it. Every query is then local, so the inputs of a run do not depend on the state of the Ensembl servers at download time, and they always come from one release.
